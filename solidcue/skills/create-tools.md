# Skill

# Create Tools

## Purpose

Define the standard contract for generating any agent `TOOLS.md` file.
This skill ensures consistent structure and behavior across different LLMs.

## When To Use

Use this skill when the system needs to create or rewrite an agent tools file.

Do not use this skill for:

- executing an existing agent
- creating the agent config
- router-only clarification
- workspace profile setup

## Required Output Contract

Every generated agent tools file must contain these sections in order:

1. `# Tools`
2. `Tool Routing`
3. `Failure Handling`
4. `Tool Notes`

## Rules

- Keep the section order stable.
- Keep headings stable.
- Do not invent tools that are not registered in the agent YAML.
- Keep wording specific to the target agent's tool list, but preserve the structure.
- If a section is not relevant, state `Not specified` rather than omitting it.

## Workflow

1. Read the source materials for the target agent.
2. Identify which tools are registered in the agent YAML.
3. Determine routing priorities and failure handling rules.
4. Write the agent tools file using the canonical contract.
5. Verify the final file matches the registered tool list.

## Required Inputs

- agent name
- agent key
- registered tool list
- tool usage constraints

## Validation Rules

- The tools file must only describe tools listed in the agent's YAML `tools:` field.
- The tools file must not invent tool names or capabilities.
- The failure handling section must be present and actionable.
- The tools file must stay consistent even when generated by different models.

## Output Contract

The generated file must be saved as:

- `solidcue/agents/<agent_key>/TOOLS.md`

And must remain compatible with the agent graph prompt loaders.
