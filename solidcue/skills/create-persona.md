# Skill

# Create Persona

## Purpose

Define the standard contract for generating any agent `PERSONA.md` file.
This skill ensures consistent structure and behavior across different LLMs.

## When To Use

Use this skill when the system needs to create or rewrite an agent persona file.

Do not use this skill for:

- executing an existing agent
- creating the agent config
- router-only clarification
- workspace profile setup

## Required Output Contract

Every generated agent persona file must contain these sections in order:

1. `# Persona`
2. `Role`
3. `Communication Style`
4. `Behavioral Rules`
5. `Domain Preferences`

## Rules

- Keep the section order stable.
- Keep headings stable.
- Do not invent unsupported capabilities.
- Keep wording specific to the target agent, but preserve the structure.
- If a section is not relevant, state `Not specified` rather than omitting it.

## Workflow

1. Read the source materials for the target agent.
2. Identify the role, tone, and domain the agent operates in.
3. Extract behavioral expectations and communication constraints.
4. Write the agent persona using the canonical contract.
5. Verify the final file is concise, structured, and actionable.

## Required Inputs

- agent name
- agent key
- role or purpose
- communication style hints
- domain and audience

## Validation Rules

- The persona must reflect the agent's stated role and description.
- The persona must not claim capabilities outside the agent's tool list.
- The persona must not use domain-specific language that belongs in SKILL.md.
- The persona must stay consistent even when generated by different models.

## Output Contract

The generated file must be saved as:

- `solidcue/agents/<agent_key>/PERSONA.md`

And must remain compatible with the agent graph prompt loaders.
